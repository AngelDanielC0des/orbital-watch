# T21 — Satellite picking accuracy + hover marker (user-reported, added by coordinator)
Tier: sonnet55-high · Wave: 8 (after T15) · Depends: T13, T15

**Report (user, verbatim intent)**: there is no indicator that each object is navigable; when the cursor is exactly over an object it must show a dot / grow to signal it can be clicked; today, clicking an object selects a *different* object on the opposite side of the planet. Picking is wrong.

**Target**: earth view picking in `src/engine/create-engine.ts` (`pointerup` / `pointermove` handlers ~L712-775) and `SatelliteLayer.pickFrom/pickAsync/pick` + `GpuPropagator.readPositions/readBuffer` in `src/engine/render/satellites.ts` and `gpu-propagator.ts`.
**Change**:
1. **Reproduce and diagnose first** (dev server, `/orbitalwatch?debug`, MCP playwright/chrome-devtools; synthetic catalog is expected in this environment, NORAD from 10000): click a visible satellite dot and record the index returned by `pick`/`pickAsync` vs the dot actually under the cursor (compute the screen position of the returned index with the same view-projection and compare to the click point). Find the root cause and state whether it pre-exists in the legacy engine logic or was introduced by the port. Candidate causes to check (do not assume): index↔texel mapping of `readPositions` (row-major / padding / `count` vs texture width), readback positions stale or in a different frame than the render (earth-fixed vs inertial: earth `surface` rotation / `gmstRad` applied to the sat group but not to the pick positions), the `w`/`c` occlusion test, filter-hidden objects (`positions[i*4+3]`) not matching the current filter, or `pickAsync` resolving after the camera moved.
2. **Fix the root cause** with the smallest change. You MAY make a minimal, documented edit in `src/engine/render/satellites.ts` / `gpu-propagator.ts` ONLY if the bug is there (no GLSL changes, no renamed public methods/exports); otherwise keep the fix in `create-engine.ts` / the layer wrappers.
3. **Hover marker** (desktop mouse, earth view, satellites layer visible): when the pointer is within the pick radius of a satellite, show a clearly visible marker on that satellite (a ring/dot ~14–18 px on screen, constant screen size, e.g. a `THREE.Points`/`Sprite` ring with `sizeAttenuation:false`, depthTest honouring Earth occlusion, additive, accent colour) that follows the object each frame while hovered; hide it on leave/occlusion/view change/pointer down-drag. Keep `canvas.classList` `is-pointing` (cursor: pointer). Implement it as a new `src/engine/layers/hover-layer.ts` (`ILayer`, copy `earth-layer.ts` K4 shape; register in `registry.ts`; `dispose()` frees geometry/material) driven only from the engine pointermove (already throttled 120 ms; keep the pick throttled but update the marker position every frame from the current index). Same for solar view bodies: hovered body gets the same marker (or a scale-up of its label). No React, no store writes per frame, no DOM by id.
**Pattern**: `src/engine/layers/earth-layer.ts` (K4) and `src/engine/layers/place-layer.ts` (a layer that is highlighted from engine code).
**Constraints**: `src/engine/contract.ts` frozen (additive-optional only via `ask`); engine boundary guard (`rg -n "from \"(react|react-dom|zustand|@/stores|@/components|@/hooks)|getElementById|querySelector|document\." src/engine/` → only the known `render/track.ts:25` hit); no `any`/`@ts-ignore`/`as unknown as`; do not break touch picking (`pointerType === "touch"` keeps radius 24 and tap-to-select), nor `pickLabel`, nor `select()/unfollow`.
